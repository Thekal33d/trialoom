This initial numeric projection trades richer context for a narrow privacy boundary.

Run `npm run buy:quote-report` to refresh the same public-safe example. No signer, payment header or wallet is available to this path. Catalog and quote bodies are bounded; redirects are refused. The private detailed response goes under ignored `artifacts/buy-reports/`.

Generated output must be complete JSON with bounded title, explanation, next step and references that exist in the original projection. Truncated responses, unknown references, added decision fields, known secret shapes, URLs and markup are refused. The resulting record is labeled `generated_explanation` and `authoritative: false`; it cannot alter test results or accept work. These syntactic checks do not establish factual correctness. Builders must see the original observations beside the explanation.

## Remaining implementation and live proof

1. Bind the projection to a completed, authorized free-beta run and store its request/evidence hash before any purchase. Exclude reports that do not need an explanation; do not generate traffic for the bounty alone.
2. Add a dedicated sponsored purchase ledger and trusted worker, one intent per report/service/version, with atomic platform and per-user allowances. Keep accepted existing marketplace liabilities separate and create no customer payable.
3. Configure a dedicated resource signer and explicitly authorized wallet/token/aggregate cap. A public user cannot supply a recipient, endpoint, model, raw prompt, wallet or amount.
4. Re-quote and validate funding; durably reserve and record public authorization fields before the single paid dispatch. Preserve response integrity and payment identity across process failures. Unknown settlement holds the reservation and must never automatically repurchase.
5. Verify a finalized exact token transfer and authorization against Celo; separately classify usable output, paid-but-unusable output and unresolved settlement. A 2xx response or provider header alone is not finality proof.
6. Persist/display the explanation with the deterministic report and keep useful-output/receipt evidence. Prove one request benefits a real external user before making integration or bounty claims.
