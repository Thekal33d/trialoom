# ERC-8004 agent identity

The event rules state that "your project will only be valid with an ERC-8004 identity", and that the agent's wallet must be added to the entry with its identity registered **from that wallet** before 2026-11-09 09:00 GMT / 10:00 Africa/Lagos. Trialoom has no agent wallet and no identity yet, so this records what is verified, what is drafted, and what is still missing.

## Verified on 2026-11-02

The Celo mainnet Identity Registry is **`0x8004A169FB4a3325136EB29fA0ceB6D2e539a432`**. Two independent sources agree — the [erc-8004 team's contracts repository](https://github.com/erc-8004/erc-8004-contracts) and [Celo's own documentation](https://docs.celo.org/build-on-celo/build-with-ai/8004) — and the address was then checked against the chain rather than taken on trust:

```
chainId      : 42220
code present : true
name         : AgentIdentity
symbol       : AGENT
```

It is an ERC-721 with URIStorage behind a small proxy. The Celo **Sepolia** registry is `0x8004A818BFB912233c491871b3d84c89A494BD9e`; testnet references are allowed in the repository but only mainnet transactions count.

The registration file format comes from [the ERC itself](https://eips.ethereum.org/EIPS/eip-8004). The on-chain `agentURI` must resolve to that file and may use any URI scheme, including `https:`, `ipfs:` and a base64 `data:` URI, so a registration does not depend on having a domain. The file links back through `registrations`, each entry carrying an `agentId` and an `agentRegistry` written as `{namespace}:{chainId}:{identityRegistry}` — here `eip155:42220:0x8004A169FB4a3325136EB29fA0ceB6D2e539a432`.

## The chicken and egg, and how to resolve it

`agentId` only exists after registering, and the file is supposed to contain it. The ERC allows for this: `register()` with no argument, then `setAgentURI(agentId, uri)` once the file is published with the id in it. The order is therefore:

1. Decide the agent wallet. It must be the wallet that sends the registration, and it is the one added to the entry.
2. Publish [`public/agent.json`](../public/agent.json) at a resolvable URI.
3. `register(agentURI)` from the agent wallet, or `register()` then `setAgentURI`.
4. Put the returned `agentId` into `registrations` and republish.

## What is still missing, and why it is blank rather than guessed

[`public/agent.json`](../public/agent.json) is the real file, not a sample, and the fields that are not yet true are **empty rather than filled with a plausible value**:

| Field | Why it is empty |
| --- | --- |
| `image` | No hosted image exists. An ERC-721 app would show a broken link. |
| `services` | Each entry needs a resolvable `endpoint`. Nothing is deployed, so there is no endpoint to name. |
| `registrations` | Filled with the `agentId` the registration returns. |
| `active` | `false` until the service actually answers. Claiming otherwise would be the one field a reader checks first. |
| `x402Support` | `false`. Trialoom pays for services; it does not charge over x402. |
| `supportedTrust` | Empty is meaningful: the ERC says the identity is then used for discovery only, which is what this is. |

Publishing it as it stands is honest and registers a discoverable identity. Filling `services` and setting `active` waits on FREE-03 hosting.
