## 2026-11-03 — BUY-01 — The x402 client, and what the gateway told us for free

- Added [`src/server/buy-x402.ts`](../src/server/buy-x402.ts), a `SponsoredAdapter` that pays buy's gateway over x402 on Celo. **Nothing has been paid**: no signer is configured, the sponsored ceiling is 0 and the wallet holds no USDC.
- **Read the token before writing anything against it.** Celo USDC reports `name` USDC, `version` 2, 6 decimals, a `TRANSFER_WITH_AUTHORIZATION_TYPEHASH` equal to the canonical EIP-3009 one, and a `DOMAIN_SEPARATOR` that the domain rebuilt from the gateway's own `extra` reproduces exactly. `authorizationState` answers, which is what makes reconciliation a chain reading rather than the provider's word.
- The adapter re-derives that comparison **before every signature**. A quote can claim any EIP-712 domain it likes, and signing against an unverified one is how a signature ends up valid somewhere nobody intended. The check is cheap and the failure mode is not.
- **Settled the wire format by probing the live gateway for free.** Sending a deliberately expired authorization signed by a throwaway key meant verification had to fail before anything could settle, so three requests cost nothing and answered the question: no header → `payment_required`; `X-PAYMENT` with the v1 payload → `verify_payment_failed: expired`, which means the signature recovered and the domain and authorization parsed; `PAYMENT-SIGNATURE` with the v2 payload → `invalid PAYMENT-SIGNATURE: accepted is missing`. v1 is implemented because it is the one verified end to end; v2 is recorded rather than guessed at.
- The live 402 lists three offers — USDC, USDT and USAT, all 10,000 base units to the same payee — and only the pinned USDC one at the pinned payee is taken.
- **The authorization nonce is the purchase's identity on chain**, derived from its intent key. One purchase always signs one authorization, the token refuses a reused one, and so a double payment is impossible at the token rather than only in our bookkeeping. `resolve` becomes exact: used means settled, unused inside the window means pending, unused past it means it can never settle.
- **The attribution question is resolved, and the answer is that we cannot tag these payments.** The facilitator sends the transaction, so this wallet has no calldata, and Celo's own documentation says facilitator-side tagging of x402 settlements is not live yet. The adapter attaches no tag and says why in its source. Crediting has to be by wallet address — the one now recorded on the entry — which agrees with the sponsor SDK's own instruction to credit `sender` rather than the transaction's `from`. Recorded as [D055](DECISIONS.md) and in [HACKATHON.md](../docs/HACKATHON.md), with a note that this is still worth one message to the organisers.
- **Fixed the flake rather than reporting it twice.** `tests/preview-command.test.ts` failed in two of three full runs: its fixture was a Node script racing a one-second deadline to write its pid, and Node's start-up loses that race on a loaded machine. Rewrote the fixture as a `/bin/sh` script that records `$$` immediately and ignores SIGTERM. No assertion, threshold or claim changed — the race is gone instead. Three isolated runs and the full suite now pass.
