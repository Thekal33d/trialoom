**M3: PILOT-05 implemented payment authority accounting and the approval every brief shares.** A per-campaign ceiling is a promise to operators and says nothing about ability to pay: on Celo one token approval backs every policy a wallet grants, which the pinned SDK's own type and the live guide both state plainly, so two live briefs could each hold an authorized ceiling, each name their own policy, and be funded by one approval only one of them could drain. The approval is now the accounted object, identified by the tuple that identifies it on chain, and one table check refuses the overcommitment. Finality **spends** the approval rather than freeing it; closing a brief returns only what no unfinalized payable still needs; a declaration can only rise, and a reading below the commitments marks the approval short and **cancels nothing**, because a spending authorization was never escrow. The live Remesso adapter is written, keeps every money-shaped decision on Trialoom's side, and puts the provider's journals, signer lock and nonce floor in Trialoom's own database so a retry on another worker cannot pay twice. `npm run payments:fork` drove the product's own path against deployed contract code on a disposable Anvil fork of Celo: a real policy, a real accepted decision, a real payable, **exactly the owed amount reaching the payee in one signed transaction**, finality read back, the approval's remainder falling, and a chain re-read agreeing. That is the first time value has moved through this code. **It is not mainnet**: loopback only, public fixture keys, and the script refuses to run with a real key configured. What the payout cost to send is now read from the transaction's own receipt and recorded once against it — the fork check confirms the agent's own balance falls by exactly that and the builder's ledger does not move — and because gas is paid in CELO while the fee is collected in USDC, the two are reported separately and never converted. That closes one of the economics target's holes **without** making it measurable: it still prints no margin. Each approval is now re-read on a timer rather than when somebody remembers — registration puts the read on the outbox, each turn reschedules itself, and a read that failed is kept strictly apart from an approval that is genuinely short, because an RPC outage must not look like insolvency. An inactive policy found by that read stops new claims, since it is the same fact a failed payout would report later; a shortfall is reported and nothing else, because the builder can top it up. **What that read finds now leaves the platform**: a condition is raised once, resolved when it stops, and delivered to the workspace's one registered HTTPS destination as a signed POST whose timestamp is signed with the body, so a captured one cannot be replayed. The record says whether anyone was told — nowhere to send, refused, or resolved before delivery are three different outcomes, not one silence — and nothing that leaves carries a key or a grant. A notice still decides nothing, and an absent provider raises none: with nothing configured the refusal is recorded as the reason the approval stays unverified, but nothing has changed about it and nobody is told. No wallet is funded.

**ALPHA-09 is complete, so a run can buy a capped resource and the cost is accounted for.** A builder's published allowance and the platform's ability to pay are separate: a resource account with its own recorded ceiling refuses what the resource wallet cannot fund, and that amount is not owed by the builder. **ALPHA-07 is complete, so the repair workflow runs end to end.** A repair is bought against one confirmed defect, one pinned build and the paths it may change, approved by the workspace owner before the brief can be published; publication is refused unless the published terms offer that same build at that same price. The quoted operator holds the first slot and everyone else verifies. A delivery that does not demonstrate a regression fix is refused outright and the whole submission rolls back, so a repair row can only exist for evidence that passed the gate. A confirmation must come from someone unconnected to the author and to every discoverer of the defect, must carry its own replays, and must exercise the same assertion the delivery was measured against. The author's work cannot be accepted until that confirmation exists, and a verifier's acceptance must state its own smaller amount. Trialoom does not merge, deploy or apply a repair, issues no repository access, and re-executes nothing.

**ALPHA-08 payables, the outbox, and settlement states are verified locally.** An accepted decision now writes its payables and queues their jobs in the same transaction, so a payment never exists without its acceptance and a rolled back decision leaves neither. Each payable fixes its recipient, token, amount, decision and assignment, and carries an immutable operation key that is also its outbox dedupe key; a retry reconciles that key instead of replacing it, so a crash after broadcast recovers the original payment and sends nothing twice. Inclusion and finality are separate states, and only finality moves accepted to finalized in the ledger. Operator payouts and platform fees are separate transfers, and a failing fee never reverses a finalized payment. A lost payment authority blocks the payout with a visible reason, keeps the debt, and pauses new claims. **No funded payment authority is configured**, so the default adapter blocks every payout and no transfer has happened; Trialoom still neither hosts nor sandboxes the runner, repairs do not exist, and resource accounting is missing. M1 still has open independent-operator and paid-resource gates.
